What is STOMP ?

STOMP = Simple Text Oriented Messaging Protocol.

For our project, think of STOMP as:

Raw websocket gives us a connection. STOMP is a set of conventions that tells us how clients and servers exchange messages over the WebSocket.

without STOMP, for every exchanging messages we have to write code to define a protocol or message structure to understand or process the message.

stomp gives us existing message models like :

CONNECT
SUBSCRIBE {url} - clients want to listen to this destination for messages
SEND
MESSAGE {url} -the server sends messages to this client because he subscribed 
DISCONNECT

analogy: HTTP protocol we have GET,POST,PUT,DELETE. we don't just send messages and expect the server to understand the operation but define it as a structure. same concept.

Retry & DLQ (Dead Letter Queue)

When notification comes for EMAIL --> consumer fetched and send to email handler --> Error ---> notification lost just saved in DB

why ? 
mail server may down
incorrect mail address
network issue
timeout
rate limit 

So we implement Retry logic . 

attempt1 --> attempt2--> attempt3 : in any of these attempts it may succeed if it's temporary failure

what if it's not succeed in these attempts, we need to park these event somewhere for later manual fix or investigation.  we can't retry forever to waste CPU usage and block useful works.

That's Dead Letter Queue. It's a Topic where failed events will be preserved. 

if our normal topic is notification-events  then the DLQ topic will be notification-events-dlt.

note: the same failed event should go into the DLQ not new one.

Retry vs Reprocessing 

retry fix if temporary failure . whereas, reprocessing is manual fix and investigation

we defined kakfa running in localhost:9092 in property file.

so either use : host.docker.internal:9092 - which conceptually does this

       ▼
Your machine
       │
       ▼
Kafka :9092

but hardcoding this ? use env variables : ${KAFKA_BOOTSTRAP_SERVERS:localhost:9092} - this means when running normally it runs spring boot --> localhost:9092 but running inside container we give env variable in command so spring boot --> host.docker.internal:9092.

Another problem :

Advertised listeners ?

when spring boot try connects to kafka in windows host using host.dokcer.internal:9092 . the kakfa would responds like my address is localhost:9092 then spring boot checks localhost 9092 inside container and could not find it :

why kakfa does this? it has 2 concepts

listeners -> where kafka actually listens 
advertised listener --> where kakfa tells client to listen

when spring boot reaches kafka by host.docker.internal:9092 the kafka gives something like ["Broker 1 is at localhost:9092"]  the container then tries localhost 9092 inside container 

solution

in server.properties in kafka folder /KRaft. change the "advertised.listeners=PLAINTEXT://localhost:9092" to "advertised.listeners=PLAINTEXT://host.docker.internal:9092"
